# Rename `resh` to `roost` — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rename the project, its binary, its environment contract, its on-disk
names and its GitHub repository from `resh` to `roost`, on the repo and on the
deploy host, without ending a single one of the live sessions the host is
running.

**Architecture:** The same three sharp edges as the previous rename
(`docs/superpowers/plans/2026-08-18-rename-to-resh.md`), each its own task:
the **crate/binary** (caught by the compiler), the **environment contract**
(`RESH_*` lives inside every terminal and in every hook — never caught by a
compiler), and **on-disk names** (state dir, config dir, project dir, lock
file `ideName`). Two things are different this time. First, **the host's state
is live, not disposable**: 14 session directories hold shells the user works
in daily, and the registry identifies a socket's holder by matching the
socket's *path* as a whole argument in `ps` output (`registry::pids_holding`),
so the state directory on the host keeps its old path via `ROOST_STATE_DIR`
rather than being moved or symlinked — either of those reads as "nothing holds
this socket" and unlinks it. Second, **`resh` is a substring of `refresh`,
`fresh` and `threshold`**, so every sweep is whole-word and case-sensitive
(`\bresh\b`, `RESH_`); the blanket `s/resh/roost/g` that worked for
`deadlight` would corrupt `refresh_live_sessions` and the vendored JS.

**Tech Stack:** Rust 2021 (no async runtime), plain JS, Deno browser tests,
systemd user units, tailscale serve. GNU sed (`\b` is supported in both basic
and extended mode).

**Spec:** None. This plan implements a naming decision taken in conversation
on 2026-09-01. Facts established then: crates.io `roost` is a squatted
"Coming soon" placeholder from 2018-12-19 and `roost-cli` belongs to an
unrelated interpreter; the user chose to keep the crate name `roost` and
defer crates.io (distribution via GitHub and `cargo install --git`
meanwhile). GitHub `PeterKnego/roost` is free; no apt package or Homebrew
formula is named `roost`. The tailnet hostname is `bajsek`, not `resh`, so
no route changes. The checkout directory `~/projects/resh` is **not** renamed
by this plan: doing so removes project `resh` from the roots and ends its
sessions, including the terminal this plan is being executed from. It is a
deferred manual step, written out at the end.

## Global Constraints

- The new name is exactly `roost`, lowercase, everywhere: crate, binary, env
  prefix (`ROOST_`), default state dir, config dir, per-project dir, systemd
  unit, IDE lock `ideName`, MCP `serverInfo.name`, log prefix.
- **No live session may end.** The deploy host (`bajsek`, which is also the
  machine this checkout is on) has 14 socket directories under
  `~/.local/state/resh/sock/` with live holders. The cutover task counts
  sockets-with-holders before and after and treats any difference as a
  failed deploy.
- **The host's state directory stays at `~/.local/state/resh/`**, selected by
  `Environment=ROOST_STATE_DIR=…` in the unit. Not moved, not symlinked (see
  Architecture). The override is documented in the unit and in the host notes.
- **Every sweep is whole-word and case-sensitive.** `git grep -w resh` and
  `git grep RESH_` define the scope; `git grep -i resh` does not (it matches
  `refresh`, `fresh`, `threshold`, `Fresh` in three vendored files and dozens
  of comments).
- **Historical design documents are not rewritten.** Everything under
  `docs/superpowers/specs/` and `docs/superpowers/plans/` dated before today
  keeps its filename and contents. Living docs (`README.md`, `CLAUDE.md`,
  `docs/deploy.md`, `docs/notifications.md`, `docs/backlog.md`,
  `tests/browser/README.md`) are updated.
- `cargo test -- --test-threads=1`, never a bare `cargo test` (it hangs on
  this host) and never `--release`. Baseline measured 2026-09-02 before any
  change: `677 passed` (lib), `66 passed` (integration), two empty result
  lines (doc tests), all `ok`.
- Every task ends green and committed. Stage explicit paths, never `git add
  -A` (it once swept uncommitted backlog notes into an unrelated commit).
- Build from this checkout only. A second checkout of this package shares the
  cargo target dir and silently rebuilds the binary from the other tree.
- Scratch files go in the session scratchpad directory, never `/tmp`.

- [ ] **Step 1: Rewrite the failing test**

Replace the whole of `a_terminal_carries_the_resh_environment_contract` in
`src/session.rs` (it starts at line 1840; keep it inside the same `mod tests`)
with this. It reads the environment back **out of a real PTY child**, because
the exported variables are invisible to the compiler. Two things are new
against the previous version: the child inherits the test process's
environment (`CommandBuilder` does not clear it), and **this host runs the
suite inside a resh terminal**, so `RESH_NOTIFY`/`RESH_PROJECT`/`RESH_SESSION`
are already in the test's own environment — the negative assertion would fail
for the wrong reason unless the test removes them first. Nothing in the crate
reads those three; they are only ever exported.

```rust
    #[test]
    fn a_terminal_carries_the_roost_environment_contract() {
        let _g = SESSION_ENV_LOCK.lock().unwrap_or_else(|e| e.into_inner());
        // `env` prints the child's environment to its stdout, which is the PTY —
        // so it arrives back through this attachment's own subscriber channel.
        std::env::set_var("ROOST_CMD", "env");
        // The child inherits this process's environment, and on the author's
        // host this suite runs *inside* a roost terminal — so the old and new
        // prefixes may both already be present, exported by the terminal we
        // are in rather than by the code under test. Clear them so the
        // assertions below see only what `session_env` exports.
        for prefix in ["RESH_", "ROOST_"] {
            for name in ["NOTIFY", "PROJECT", "SESSION"] {
                std::env::remove_var(format!("{prefix}{name}"));
            }
        }
        let d = tempfile::tempdir().unwrap();
        let att = reserve_and_attach("envproj", "shell", d.path()).expect("attach");

        let deadline = std::time::Instant::now() + std::time::Duration::from_secs(10);
        let mut seen = String::new();
        while std::time::Instant::now() < deadline {
            match att.rx.recv_timeout(std::time::Duration::from_millis(250)) {
                Ok(chunk) => {
                    seen.push_str(&String::from_utf8_lossy(&chunk));
                    if seen.contains("ROOST_SESSION") {
                        break;
                    }
                }
                Err(_) => {}
            }
        }
        kill_project("envproj");
        std::env::remove_var("ROOST_CMD");

        assert!(seen.contains("ROOST_NOTIFY=1"), "child env lacked ROOST_NOTIFY: {seen:?}");
        assert!(seen.contains("ROOST_PROJECT=envproj"), "child env lacked ROOST_PROJECT: {seen:?}");
        assert!(seen.contains("ROOST_SESSION=shell"), "child env lacked ROOST_SESSION: {seen:?}");
        // concat! keeps the literal out of the whole-repo sweeps that verify
        // the old prefix is gone.
        assert!(
            !seen.contains(concat!("RESH", "_")),
            "a terminal still exports the old prefix, so hooks would see both: {seen:?}"
        );
    }
```

```markdown
setting `ROOST_STATE_DIR=$HOME/.local/state/resh` in the unit. The author's
own host does the latter.

`{project}/.resh/` to `{project}/.roost/` (`config.toml` and `theme/`). A
project still carrying only the old `.resh/` directory silently loses its
theme and hide settings — `.roost/` is what gets read now, and nothing
migrates the old one automatically. Verified 2026-09-02: no project under the
deploy host's roots has a `.resh` directory. Rename it by hand (`git mv .resh
.roost` inside the project, if it's tracked) on any project that carries one.
```

`%h` is the user's home in a user unit. The comment on the state dir is the
one thing a future reader must not "clean up".

```bash
cat > ~/.config/systemd/user/roost.service <<'UNIT'
[Unit]
Description=roost — remote web workspace
After=network.target

[Service]
# KillMode=process is load-bearing: roost spawns dtach sessions as children so
# shells survive a restart. The default control-group KillMode kills the whole
# cgroup and takes every session with it.
KillMode=process
Environment=ROOST_ROOTS=/home/claude/ultima:/home/claude/projects
# The state directory keeps its pre-rename path ON PURPOSE. Every live dtach
# master was spawned with a socket path under ~/.local/state/resh in its
# argument list, and the registry identifies a socket's holder by matching
# that exact path in `ps` output. Under a new path — moved or symlinked —
# every socket reads as held by nothing and is unlinked, leaving its shell
# alive and unreachable. Migrate only when no session is live: stop roost,
# move the directory, drop this line, start.
Environment=ROOST_STATE_DIR=%h/.local/state/resh
ExecStart=%h/.local/bin/roost
Restart=on-failure
WorkingDirectory=/home/claude/projects/resh

[Install]
WantedBy=default.target
UNIT
systemd-analyze --user verify ~/.config/systemd/user/roost.service && echo unit-ok
```

- [ ] **Step 4: Cut over, in one command so the gap is seconds**

The old service's four IDE lock files (`~/.claude/ide/*.lock`, all
`"ideName": "resh"`, all pointing at the old main pid) must go by hand: the
new binary's startup reap only touches files that say `roost`, so they would
sit there forever and Claude Code would keep offering a dead "resh" IDE.
The removal is gated on the pid being dead *and* `/proc` being readable —
the same three-way check `health.rs` makes.

```bash
systemctl --user stop resh && systemctl --user disable resh
mv ~/.local/bin/resh ~/.local/bin/resh.pre-roost && ln -s roost ~/.local/bin/resh
mv ~/.config/resh ~/.config/roost
rm ~/.config/systemd/user/resh.service
python3 - <<'PY'
import json, os, glob
for f in glob.glob(os.path.expanduser("~/.claude/ide/*.lock")):
    try:
        v = json.load(open(f))
    except Exception:
        continue                      # someone else's malformed file is not ours
    if v.get("ideName") != "resh":
        continue
    pid = v.get("pid")
    if not os.path.isdir("/proc"):
        print("cannot tell whether", pid, "is alive: no /proc; leaving", f); continue
    if os.path.exists(f"/proc/{pid}"):
        print("still alive:", pid, "leaving", f); continue
    os.remove(f); print("removed stale resh lock", f)
PY
systemctl --user daemon-reload && systemctl --user enable roost && systemctl --user start roost
sleep 4; systemctl --user is-active roost
```

Expected: four `removed stale resh lock` lines, then `active`.

## Deferred: renaming the checkout directory

Not a task in this plan. `~/projects/resh` is project `resh` in roost's own
roots, and it has live sessions — including the two worktree Claudes and the
terminal this plan is executed from. Moving the directory makes the project
vanish from the roots, and the registry then ends its sessions (with the
`.origin` marker as its evidence). Do it when those sessions are finished
with, in this order:

1. Close every session of project `resh` and of its two worktrees from the
   workspace UI, so nothing relies on the reaper.
2. `systemctl --user stop roost`
3. `mv ~/projects/resh ~/projects/roost && cd ~/projects/roost && git worktree repair`
   — the worktrees' `.git` files hold the old absolute path.
4. `sed -i 's#WorkingDirectory=/home/claude/projects/resh#WorkingDirectory=/home/claude/projects/roost#' ~/.config/systemd/user/roost.service && systemctl --user daemon-reload`
5. `cp -r ~/.claude/projects/-home-claude-projects-resh ~/.claude/projects/-home-claude-projects-roost`
   — Claude Code keys its memory and session history by checkout path; without
   this the next session in the new directory starts with no memory.
6. `systemctl --user start roost`, then update the Checkout row in
   `~/.config/roost/deploy-host.md`.

## Rollback
